02 — Step-by-Step Flow
🤖  AI / MCP Flow
1
MCP performs a Jira action
Creates issue, changes status, adds comment, logs work — via Jira REST API
POST /rest/api/2/issue/{key}/transitions
{ transition: { id: "21" } }
2
Immediately call Worklog Property API
Same MCP code block — right after the action — writes the source tag
PUT /rest/api/2/issue/{key}
  /worklog/{id}/properties/worklog-source
{ source: "AI_MCP" }
3
Tag stored silently in Jira
Invisible in Jira GUI. Only readable via API. No noise in the issue view.
👤  Human / GUI Flow
1
Human acts in Jira browser UI
Developer changes status, adds comment, updates field — through the normal Jira interface
2
Jira fires a Webhook to your server
Your registered webhook receives the event with actor email and issue key
{
  webhookEvent: "jira:issue_updated",
  user: { emailAddress: "john@co.com" },
  issue: { key: "PROJ-123" }
}
3
Server checks: is this the MCP bot?
If email ≠ mcp-bot@company.com → it's a human. Write the Human tag immediately.
PUT /rest/api/2/issue/{key}
  /worklog/{id}/properties/worklog-source
{ source: "HUMAN" }
🗄️
Both flows converge at the same place — Jira Worklog Properties
Every single action — AI or Human — ends up tagged with its source in the Jira worklog entity property store. No external database needed. Jira holds all the data.
PUT /worklog/{id}/properties/worklog-source

04 — APIs Used (All Existing Jira REST API v2)
# Method Endpoint Purpose Who Calls It
1 PUT /issue/{key}/worklog/{id}/properties/worklog-source Write AI or Human source tag onto worklog Both
2 GET /issue/{key}/worklog/{id}/properties/worklog-source Read back the source tag for any worklog entry Dashboard
3 GET /search?jql="Epic Link"=EPIC-42 Fetch all issues under a given Epic Dashboard
4 GET /search?jql=fixVersion="PI-3" Fetch all issues under a given PI Dashboard
5 POST /webhook Register webhook to catch human GUI actions One-time setup
6 GET /issue/{key}/worklog List all worklogs on an issue for querying Dashboard
All APIs are existing Jira REST API v2 endpoints — no plugins, no schema changes, no new APIs created  ·  Tags are invisible in Jira GUI — stored only as entity properties  ·  Dashboard queries Jira directly at any time
